<h2>一、快速开始部署</h2>
<h3>1. 环境配置</h3>
<p>在开始之前，请确保你的电脑已安装以下运行环境，否则后续程序将无法正常启动：</p>
<ul>
<li><strong>Node.js</strong> (推荐版本 v18.x 或以上)</li>
<li><strong>包管理器</strong> (npm)</li>
<li><strong>Git</strong> (用于拉取代码与版本控制)</li>
<li><strong>Python</strong> (建议版本 3.10 及以上，本系统在 3.10 环境下测试通过)</li>
<li><em>可选：云存储/图床服务（后续会有详细配置说明）</em></li>
</ul>
<h3>2. 博客源码更新</h3>
<p>为了让你能轻松跟上项目的最新功能，请使用更新器对源码进行更新！
使用更新器，你不需要再手动对比代码、不用担心拉取更新会引发冲突，更不用害怕辛辛苦苦写的文章和配置文件被覆盖！</p>
<p>🛠️ 更新步骤：</p>
<p>第一步：获取无损更新器 (仅首次需要)</p>
<h4>1 下载项目根目录下的 update.bat 和 update.py 文件。</h4>
<h4>2  将下载好的 update.bat 和 update.py 移动到你本地博客项目的最外层根目录（也就是和 my-blog-manager、XHBlogs 文件夹放在一起的地方）。</h4>
<p>如下图所示</p>
<p><img src="picture/333.png" alt="img.png"></p>
<h4>3 双击update.bat文件实现更新，如果闪退 请使用cmd运行update.py文件</h4>
<h3>3. 快速开始</h3>
<h4>① 启动脚本</h4>
<p>当你完成上述环境的配置后，恭喜你，最基础的准备工作已经搞定了！
首先，进入 <code>my-blog-manager</code> 文件夹（<strong>⚠️ 注意：请绝对不要重命名此文件夹，否则会导致环境路径解析失败！</strong>）</p>
<p>双击运行文件夹中的启动脚本：
<code>Start.bat</code>
脚本会自动检测并安装所需的依赖包。等待环境配置完成后，程序会自动唤起精美的后台控制台。</p>
<h4>② 部署你的博客到 Vercel</h4>
<blockquote>
<p><strong>提示</strong>：本教程主要演示如何将项目部署至 Vercel，因为 Vercel 对 Next.js 框架有着最顶级的原生支持。</p>
<p><strong>前提</strong>：请确保已安装 Git，并拥有一个 GitHub 账号。<strong>接下来的步骤请务必按顺序操作！</strong></p>
</blockquote>
<blockquote>
<p><strong>请确保你已完成以下操作</strong>：</p>
<p><strong>第一步：本地全局配置</strong></p>
</blockquote>
<p>设置用户名</p>
<p><code>git config --global user.name "你的Github用户名"</code></p>
<p>设置邮箱（必须是你在 GitHub 绑定的邮箱）</p>
<p><code>git config --global user.email "你绑定在Github的邮箱@example.com"</code></p>
<blockquote>
<p><strong>第二步：初始化本地仓库</strong></p>
<p>进入你的项目文件夹，执行以下CMD命令行操作：(及前端部署文件夹，这里是XHBlogs)</p>
</blockquote>
<ol>
<li>初始化 Git 仓库，生成隐藏的 .git 文件夹
<code>git init</code></li>
<li>将所有文件添加到暂存区（注意后面有个点）
<code>git add .</code></li>
<li>提交到本地版本库，并添加备注
<code>git commit -m "first commit"</code></li>
</ol>
<p><strong>1. 配置本地物理路径</strong>
打开控制台的“设置”页面。
在拉取的源码中，包含 <code>XHBlogs-mananger</code> 和 <code>XHBlogs</code> 两个核心文件夹。请在控制台中指定 <code>XHBlogs</code> 的本地物理路径。</p>
<p><img src="picture/Pasted%20image%2020260427111646.png" alt="选择物理路径"></p>
<p>例如：<code>F:\Test2\XHBlogs</code></p>
<p><img src="picture/Pasted%20image%2020260427112311.png" alt="填入本地BLOG物理路径"></p>
<blockquote>
<p><strong>关键步骤</strong>：填入路径后，请务必点击 <strong>[测试路径]</strong> 进行连通性验证！！！验证通过后，再点击下方的 <strong>[保存双轨配置]</strong>。</p>
</blockquote>
<p><strong>2. 在 GitHub 创建私有仓库</strong>
登录 GitHub，新建一个用于托管博客源码的仓库（建议设置为 <strong>Private 私有仓库</strong> 以保护数据隐私）。</p>
<p><img src="picture/Pasted%20image%2020260427112905.png" alt="创建仓库"></p>
<p>仓库名称可自定义。</p>
<p><img src="picture/Pasted%20image%2020260427113030.png" alt="仓库命名"></p>
<p>获取该仓库的 SSH 地址，并将其复制粘贴到控制台的“B线”配置中：</p>
<p><img src="picture/Pasted%20image%2020260427113120.png" alt="复制SSH"></p>
<p>源码分支填写为 <code>main</code>。确认无误后，再次点击 <strong>[保存双轨配置]</strong>。</p>
<p><strong>3. 获取并配置部署密钥</strong>
点击控制台中的 <strong>[获取B线专属密钥]</strong> 按钮：</p>
<p><img src="picture/98b965b5-6193-4690-a478-fe1a9abd594e.png" alt="专属密钥"></p>
<p>进入你的 GitHub 仓库页面，导航至 <code>Settings</code> -> <code>Deploy keys</code> 界面：</p>
<p><img src="picture/Pasted%20image%2020260427113705.png" alt="Deploy Keys"></p>
<p>将刚才复制的密钥填入 <code>Key</code> 框中，<code>Title</code> 可随意命名（例如：<code>XHBlogs-Deploy-Key</code>）。</p>
<blockquote>
<p><strong>🚨 严重警告</strong>：下方的 <strong>Allow write access</strong> 选项必须勾选！！！
设置完毕后，点击 <strong>Add key</strong> 保存。</p>
</blockquote>
<p><strong>4. 初始化并推送源码</strong>
返回本地控制台，点击 <strong>[智能初始化双轨环境]</strong>，静待程序执行完毕。
完成后，点击 <strong>[仅同步源码]</strong> 按钮：</p>
<p><img src="picture/Pasted%20image%2020260427121539.png" alt="仅同步源码"></p>
<p>程序将开始向 GitHub 推送代码。<strong>在此期间，请千万不要切换页面或关闭窗口</strong>：</p>
<p><img src="picture/Pasted%20image%2020260427121702.png" alt="同步进度"></p>
<p>进度条完成后，说明前端静态页面源码已成功托管至 GitHub。</p>
<blockquote>
<p><strong>此处可能出现无法推送bug</strong>：</p>
<p><strong>请尝试</strong></p>
<p>将SSH仓库地址改成如下图所示再进行初始化及同步源码</p>
<p><img src="picture/img.png" alt="img.png"></p>
</blockquote>

访问 Vercel 官网，注册账号并绑定你的 GitHub 授权！</p>
<p><img src="picture/Pasted%20image%2020260427121844.png" alt="绑定账号"></p>
<p>点击 <code>Add New...</code> 添加一个新的 Project，在 Import 列表中选择你刚刚推送到 GitHub 的仓库：</p>
<p><img src="picture/Pasted%20image%2020260427121939.png" alt="导入项目"></p>
<p>例如我选择的是 <code>XHBlogS2</code>：</p>
<p><img src="picture/Pasted%20image%2020260427122034.png" alt="选择项目"></p>
<p>在 Framework Preset（框架预设）中选择 <strong>Next.js</strong>，然后点击 <strong>Deploy</strong> 按钮开始部署：</p>
<p><img src="picture/Pasted%20image%2020260427122141.png" alt="点击Deploy"></p>
<p>静候 Vercel 服务器构建你的博客~~</p>
<p><img src="picture/Pasted%20image%2020260427122245.png" alt="部署中"></p>
<p>撒花！部署成功后，点击预览图即可直接访问你的专属网站！</p>
<p><img src="picture/Pasted%20image%2020260427122338.png" alt="部署成功"></p>

<h3>问题 1：我要怎么样绑定自己的专属域名？</h3>
<p><strong>答：</strong> 这里以“阿里云”购买的域名为例（其他服务商如腾讯云、Cloudflare 等操作逻辑基本一致）。</p>
<p>首先登录阿里云控制台，进入【域名管理】页面：</p>
<p><img src="picture/Pasted%20image%2020260427123636.png" alt="域名管理"></p>
<p>点击对应域名右侧的【解析】按钮：</p>
<p><img src="picture/Pasted%20image%2020260427123737.png" alt="点击解析"></p>
<p>接着回到 Vercel，进入你的项目仪表盘，点击 <strong>Settings</strong>（或者直接点击域名旁的加号）：</p>
<p><img src="picture/Pasted%20image%2020260427123156.png" alt="点击加号"></p>
<p><img src="picture/Pasted%20image%2020260427123838.png" alt="进入设置"></p>
<p>在 Domains 选项卡中，输入你购买的域名（例如我的是 <code>xinghuisama.top</code>），点击 <strong>Add</strong> 保存：</p>
<p><img src="picture/afb9fe5f-bf1e-4a8a-ae6b-379938f0924d.png" alt="输入域名"></p>
<p>添加后，Vercel 会提供 <code>A</code> 记录和 <code>CNAME</code> 记录的配置参数。请将这些参数完整添加到阿里云的 DNS 解析设置中：</p>
<p><img src="picture/Pasted%20image%2020260427124533.png" alt="添加记录"></p>
<blockquote>
<p><strong>注意</strong>：添加记录时，请务必仔细核去记录类型和记录值（Value）！</p>
</blockquote>
<p>配置完成后等待几分钟（DNS 传播需要时间），在 Vercel 页面点击 <strong>Refresh</strong> 刷新状态！！</p>
<p><img src="picture/Pasted%20image%2020260427124625.png" alt="Refresh"></p>
<p>当状态显示为正常后，你就可以通过自己的专属域名访问博客了！（例如：<code>www.xinghuisama.top</code>）。</p>
<hr>
<h2>二、更新设置及上传文件</h2>
<p>为了保护数据安全，本控制台采用了**“操作暂存区”**机制。<strong>请特别注意！！</strong> 许多设置在修改后，必须主动执行“更新到本地”才能真正保存。需要执行此操作时，界面上方通常会有高亮提示。</p>
<p><strong>操作示例：修改个人简介</strong></p>
<p><img src="picture/Pasted%20image%2020260427125314.png" alt="修改简介"></p>
<p>修改内容后，点击 <strong>[暂存到操作队列]</strong>：</p>
<p><img src="picture/Pasted%20image%2020260427125430.png" alt="暂存队列"></p>
<p>此时上方工具箱会提示待办操作。你可以随时撤销（清空全部），或者点击 <strong>[更新本地]</strong>。</p>
<blockquote>
<p>⚠️ 注意：点击“更新本地”后，数据仅仅保存在了你的本地控制台环境中。</p>
</blockquote>
<p>如果你希望让这些修改在前端博客页面生效，你必须继续点击 <strong>[同步 Blog]</strong>（前提是前端博客的物理路径已正确配置）：</p>
<p><img src="picture/Pasted%20image%2020260427125800.png" alt="同步Blog"></p>
<p>博客文章、说说（碎碎念）、杂谈等所有内容的发布与修改，均遵循此流程。</p>
<blockquote>
<p><strong>💡 黄金法则</strong>：暂存队列 -> 更新本地 -> 同步Blog</p>
</blockquote>
<hr>
<h2>三、如何推送你的修改到线上网页？</h2>
<p>当你在本地完成了满意的创作或设置调整，想要将其发布到公网让所有人看到时：</p>
<p>请牢记，在执行了任何实质性修改并点击 <strong>[同步Blog]</strong> 后，请打开控制台的同步部署页面：</p>
<p><img src="picture/Pasted%20image%2020260427130216.png" alt="打开同步"></p>
<p>确认“B线”地址正确无误，点击 <strong>[仅同步源码]</strong>。
等待 GitHub Actions 或 Vercel 自动捕获更新。稍作喝杯茶的功夫，你就能在线上页面看到最新鲜的内容了！</p>

<h2>四、图床配置</h2>

如果你习惯使用纯外链，工具台也完美支持直接插入图片 URL。如果想接入其他支持标准 API 的图床，也欢迎极客们自行尝试。</p>
<p><strong>配置流程：</strong></p>
<p><img src="picture/Pasted%20image%2020260427124930.png" alt="图床配置"></p>
<p>填入对应的 API Token 等信息后，你可以点击 <strong>[发送探针测试Token]</strong>，实时检验图床接口是否畅通。</p>

<h2>五、AI 猫猫助理设置</h2>
<p>博客系统内置了一只聪明的 AI 猫猫助理（默认接入 Gemini 模型）。极客玩家也可以通过修改源码接入其他大语言模型。</p>
<p>首先，你需要申请一个 Gemini 的 API Key（申请教程网络资源丰富，在此不赘述）。拿到 API Key 后，在控制台进行如下配置：</p>
<p><img src="picture/Pasted%20image%2020260427134211.png" alt="猫猫设置"></p>
<p>在本地设定好猫猫的专属系统提示词（性格）后，我们需要让线上环境也拥有调用 AI 的能力。请登录 Vercel：</p>
<p><img src="picture/Pasted%20image%2020260427134538.png" alt="Vercel环境"></p>
<p>在项目设置中找到 <code>Environment Variables</code>（环境变量）：</p>
<p><img src="picture/Pasted%20image%2020260427134633.png" alt="搜索变量"></p>
<p>进入你的博客工程详情：</p>
<p><img src="picture/Pasted%20image%2020260427134703.png" alt="项目工程"></p>
<p>确保作用域（环境）包含线上环境，点击 <strong>Add Environment Variables</strong>：</p>
<p><img src="picture/Pasted%20image%2020260427135004.png" alt="添加变量"></p>
<p>安全地注入你的密钥：</p>
<ul>
<li><strong>Key</strong> 输入：<code>GEMINI_API_KEY</code></li>
<li><strong>Value</strong> 输入：你的真实 API 密钥</li>
</ul>
<p><img src="picture/Pasted%20image%2020260427135044.png" alt="输入API"></p>
<p>点击保存。下一次重新部署时，猫猫助理就会在线上苏醒了。</p>

<h2>六、评论系统配置</h2>
<p>本博客的评论系统基于 GitHub Issues（Gitalk 等类似方案）。你需要在 GitHub 创建一个 <strong>Public（公开）</strong> 仓库来专门存储网友的留言。</p>
<p>在控制台评论设置中，填入你的 GitHub 用户名以及这个公开仓库的名称：</p>
<p><img src="picture/a3b44842-696b-4764-9cdf-882cd8792729.png" alt="评论设置"></p>
<p><strong>接下来，配置 OAuth 授权以允许访客登录留言：</strong></p>
<ol>
<li>登录 GitHub，点击右上角个人头像，进入 <strong>Settings</strong>（设置）。</li>
<li>滑动到左侧菜单栏最底部，点击 <strong>Developer settings</strong>。</li>
<li>在左侧选择 <strong>OAuth Apps</strong>，点击右上角的 <strong>New OAuth App</strong>。</li>
</ol>
<p><strong>关键应用信息填写指南：</strong></p>
<br/>
<table>
<thead>
<tr>
<th>字段名称</th>
<th>填写建议</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>Application name</strong></td>
<td>自定义名称，例如：<code>My-Blog-Comments</code></td>
</tr>
<tr>
<td><strong>Homepage URL</strong></td>
<td>你的博客<strong>首页完整地址</strong> (例如 <code>https://www.xinghuisama.top</code>)</td>
</tr>
<tr>
<td><strong>Application description</strong></td>
<td>可选填</td>
</tr>
<tr>
<td><strong>Authorization callback URL</strong></td>
<td><strong>核心参数</strong>：必须填写你的博客域名。如果经常本地调试，可填 <code>http://localhost:3000</code></td>
</tr>
</tbody>
</table>
<p><strong>提取核心密钥：</strong></p>
<ol>
<li>提交注册（Register application）。</li>
<li>在跳转页面即可看到 <strong>Client ID</strong>，这是所需的第一项数据。</li>
<li>点击下方的 <strong>Generate a new client secret</strong> 生成密钥。</li>
<li><strong>🚨 立刻将这串密钥复制并妥善保存！</strong> 出于安全机制，离开此页面后该密钥将永远隐藏。</li>
</ol>
<p>将这组 <code>Client ID</code> 和 <code>Client Secret</code> 准确填入控制台的对应栏目中，保存即可激活评论功能。</p>
